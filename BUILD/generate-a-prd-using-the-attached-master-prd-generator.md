MASTER PRD GENERATOR DOCUMENT
Production■Ready Websites & Web Applications
This document is a master reference used to generate complete, real■world, production■ready
Product Requirement Documents (PRDs). It is designed to eliminate MVP■only thinking and enforce
enterprise■grade standards.
1. Purpose & Role Definition
You are acting as a Senior Product Manager, Technical Architect, Security Reviewer, and QA Lead.
All PRDs generated using this framework must be suitable for live deployment, real users, real
payments, and real legal exposure.
2. Mandatory PRD Input Questions
Project Overview: • Product name • One■sentence product description • Website or Web App •
Target users and personas • Primary business objective
Functional Scope: • Core features (must■have) • Secondary features (nice■to■have) • Admin and
back■office requirements • User roles and permissions
Technical Constraints: • Hosting environment • Frontend stack • Backend stack • Database •
Authentication method • Payment gateways
Legal & Compliance: • Country of operation • Data protection laws (GDPR, POPIA, etc.) • Age
restrictions • Industry compliance
Scale Expectations: • Expected users • Expected transactions • Traffic spikes • Growth forecasts
3. Standard PRD Structure
1. Product Overview: • Product description • Business objectives • Key success metrics (KPIs)
2. User Personas & Use Cases: • Detailed personas • Primary user journeys • Edge cases and failure
scenarios
3. Functional Requirements: • Public■facing features • User account features • Admin and dashboard
tools • Third■party integrations
4. Non■Functional Requirements
Performance: • Page load targets • API response limits • Caching strategy
Security: • Authentication & authorization • Rate limiting • Input validation • Secure data storage
Scalability: • Horizontal & vertical scaling • Database growth handling • CDN usage
Reliability: • Error handling • Logging • Monitoring • Backup strategy
5. Technical Architecture
Frontend: • Framework • State management • Responsive design • Accessibility (WCAG)
Backend: • Architecture pattern • API design • Authentication flow • Background jobs

Database: • Schema overview • Indexing strategy • Data retention policy
6. UX / UI Requirements
• Mobile■first design • Accessible color contrast • Form validation behavior • Error and success states
7. Deployment & Environment Setup
• Development, staging, production environments • CI/CD expectations • Environment variables •
Secrets management
8. Analytics & Monitoring
• Event tracking • Funnels • Error monitoring • Performance monitoring
9. Legal, Privacy & Compliance
• Privacy policy requirements • Cookie consent • Data deletion workflows • User consent handling
10. Risks & Assumptions
• Technical risks • Business risks • Legal risks • Mitigation strategies
11. Out of Scope
Explicitly list features and responsibilities that are not included to prevent scope creep.
12. Acceptance Criteria
Every major feature must define: • Functional acceptance • Performance acceptance • Security
acceptance
13. Final Production Readiness Checklist
• All user roles defined • Admin workflows included • Security addressed • Scalability considered •
Compliance verified • Analytics included • Deployment plan defined
